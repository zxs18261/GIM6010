# ADR-0004：单UART手动切换TEXT与JustFloat调试模式

**状态：** Accepted  
**日期：** 2026-08-25  
**决策者：** 项目用户

## 背景

当前USART1以921600-8N1持续发送36通道JustFloat。该方案适合高速曲线，但启动、Flash加载、预定位和故障过程只能从大量数值中反推，且148字节、500 Hz的帧占用约80.3%物理链路。用户已明确接受在VOFA+中手动切换RawData与JustFloat数据引擎。

## 决策

USART1保留为唯一调试串口，并由一个发送管理器独占TX DMA。复位后进入TEXT状态，发送结构化UTF-8事件并响应只读查询；操作者在安全待机状态下通过`STREAM=1?`显式进入14通道JustFloat，通过`STREAM=0?`返回TEXT。两种上行格式不允许交叉发送，运行事件保存在本次上电有效的RAM环形队列中。

数据流切换命令只改变通信状态，不改变`AO/BO/CO/VO`、控制模式、DQ电压、PWM比较值或TIM1 MOE。故障和重新初始化会停止JustFloat；普通停机保留数据流，以便观察停机后的动态。

## 考虑过的方案

### 方案A：单UART、手动切换两种模式

- 优点：复用现有硬件和VOFA+数据引擎；JustFloat仍可保持500 Hz；无需自定义上位机插件。
- 缺点：操作者需要按规定顺序手动切换数据引擎；JustFloat期间不能直接看到文本。

### 方案B：全部使用FireWater或其他文本数值协议

- 优点：事件和数值可以在同一文本流中阅读。
- 缺点：浮点转文本和更高字节量会增加MCU与串口负担，不利于后续电流环高速波形观察。

### 方案C：自定义复合协议或第二路调试串口

- 优点：能够同时显示事件和曲线。
- 缺点：需要额外上位机插件或硬件资源，明显超出当前开环调试的最小范围。

## 后果

- `Sguan_printf`成为USART1 TX DMA的唯一所有者，并维护TEXT、STARTING、JUSTFLOAT、STOPPING四态。
- 中断只提交命令结果或事件码；中文格式化、Flash只读诊断和UART发送均在主循环或校准后台服务中完成。
- 操作者错过启动文本时通过`LOG?`回放本次启动事件；运行日志不跨掉电保存。
- 后续电流环、速度环和位置环需要分别批准新的JustFloat通道合同。
- VOFA配置、协议文档和调试步骤必须与固件状态机同步更新。
