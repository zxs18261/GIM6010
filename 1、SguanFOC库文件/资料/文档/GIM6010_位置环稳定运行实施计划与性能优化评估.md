# GIM6010：从当前开环到稳定快速位置环的实施计划与性能优化评估

> 评估日期：2026-08-21  
> 范围：当前 STM32G431 + GIM6010 + SguanFOC 工程的源码静态评估。  
> 本文不代表已经完成实机验证；相序、方向、负载惯量和供电能力必须以台架测试为准。

## 1. 先给结论

当前工程已经具备低风险开环验证所需的基本链路：

~~~text
开环角度积分 + Uq 给定
    -> 逆 Park / SVPWM
    -> TIM1 三相互补 PWM
    -> GIM6010 功率级
~~~

但它还不具备“直接开启位置环并快速、稳定响应”的条件。当前的主要问题不是单纯 PID 参数，而是实时任务架构、采样/保护完整性、位置单位约定和编码器数据路径尚未收敛。

尤其不能直接将 mode 切到 PosVelCur_THREE_MODE 后开始调 Position.Kp。这样得到的结果往往是抖动、失步、超调或偶发停机，且无法定位是电流、速度、位置、编码器还是保护逻辑的问题。

建议遵循本文第 5 节的阶段顺序。每一阶段都有独立验收门槛，未通过时不要进入下一阶段。

## 2. 当前工程的实际控制架构

### 2.1 当前执行路径

当前 TIM1 产生约 20 kHz 三相 PWM，并通过 CH4 触发 ADC 注入采样。实际控制计算却由 TIM2 的 1 kHz 更新中断执行：

~~~text
TIM1（约 20 kHz）
  -> 三相 PWM、CH4 触发 ADC 注入采样

TIM2（1 kHz）
  -> SguanFOC_High_Loop()
      -> 读取 MT6816（同步 SPI）
      -> 读取最近 ADC 注入结果
      -> Clarke/Park、模式控制、SVPWM
  -> SguanFOC_Low_Loop()
      -> 状态机、保护逻辑

主循环
  -> RGB 轮询
  -> SguanFOC_main_Loop()
  -> VOFA 数据打包和 UART DMA 发送
~~~

对应源码位置：

- TIM2 调度：Hardware/Timer.c 第 25 至 33 行
- TIM2 运行时改为 1 kHz：Core/Src/tim.c 第 150 至 154 行
- PWM 频率和中心对齐配置：Core/Src/tim.c 第 46 至 101 行
- 控制主路径：SguanFOC/SguanFOC.c 第 1575 至 1671 行

### 2.2 当前位置环为何不适合追求快速响应

UserData_Config.h 中 TIM_T 仍为 100 us，而 High_Loop 的真实频率是 1 kHz，即真实周期为 1 ms。滤波器、PLL、PID 的离散化参数按 100 us 初始化，却按 1 ms 的物理时间运行。

此外，当前 Response = 5。按实际 1 kHz High_Loop 计算：

- 电流环：1 kHz
- 速度环：约 200 Hz
- 位置环：约 40 Hz

位置环 40 Hz 可以用于低动态演示，但不适合“给定一个位置角度能够快速响应”的伺服目标。更关键的是，电流环只有 1 kHz，无法为快速速度环、位置环提供足够的带宽和抗扰能力。

相关源码：

- 基准周期：SguanFOC/UserData_Config.h 第 70 至 72 行
- Response 设置：SguanFOC/UserData_Parameter.h 第 57 行
- 三环分频：SguanFOC/SguanFOC.c 第 457 至 550 行

## 3. 个人配置阶段必须处理的事项

以下项目按优先级排列。前四项应视为进入闭环前的必做项。

### 3.1 必做：统一控制周期

当前存在 1 ms 实际执行周期与 100 us 参数周期不一致的问题。

短期仅用于开环、编码器和 ADC 验证时，可将 TIM_T 临时统一为 0.001f，使 PLL、滤波器和控制器的离散时间与 TIM2 对齐。此方案不能作为最终快速位置环架构。

最终方案建议改为多速率任务：

- 电流环：20 kHz，跟随 TIM1/ADC 的 PWM 同步时刻执行。
- 编码器采样：2 至 5 kHz，采用缓存或 DMA，不能阻塞电流环。
- 速度环：1 kHz 左右。
- 位置环：250 至 500 Hz 起步；负载轻、编码器数据和速度估计足够好时再提高。
- 保护与状态机：1 kHz。
- VOFA 常规遥测：100 至 200 Hz。

### 3.2 必做：确认双电阻电流相序和电流方向

板卡硬件实际采样的是 V 相和 W 相：

- ADC1_IN12 / PB1：IV
- ADC1_IN15 / PB0：IW

工程引脚文档将这组采样建议为 Current_Num = 1，但当前 UserData_Motor.h 设置为 Current_Num = 0，且注释仍称 IV + IW 为 BC。这三者彼此不一致。

电流增益也存在冲突：当前代码把 Amplifier 设置为 20，而板级引脚文档记录 U15/U16/U19 的默认增益为 10。若实际硬件确为 10 倍，当前换算的电流值会约为真实值的一半，电流环和过流保护均不可信。

错误的相电流映射会导致：

- Id、Iq 的符号或幅值不正确；
- 过流判断失真；
- 电流环无法整定；
- 速度和位置环即使参数正确也会抖动或反向。

在低压、限流、空载条件下，应依次确认：

1. 三相 PWM 的逻辑相 U/V/W 与实际功率相一致。
2. 两路 ADC 零电流偏置正确，静止时 Ia、Ib、Ic 近似为零。
3. 小 Uq 开环转动时，估算相电流和实际转向一致。
4. 轻推转子时，编码器方向、机械速度符号和电角度变化方向一致。
5. 通过实际测试确定 Current_Num、Current_Dir0、Current_Dir1、Motor_Dir、PWM_Dir、Encoder_Dir 的最终组合，并记录到板级文档。

不要根据相线颜色或猜测固定这些参数。

### 3.3 必做：实现真实保护和安全关断

当前 User_VBUS_DataGet 和 User_Temperature_DataGet 固定返回 -9999，因此母线电压、温度相关保护没有生效。状态处理回调中也大多为空，急停状态并未形成明确的 PWM 硬关闭动作。

在进入电流环以前，应实现：

- ADC 常规通道读取 VBUS 和温度，并滤波、标定。
- Id、Iq 过流采用绝对值判断，而不是仅判断正方向超限。
- 出现过流、编码器失效、急停、PWM 计算故障时，立即把 TIM1 的 MOE 关闭，或利用硬件 Break 输入关断。
- 重新使能前清空 PID 积分、目标速度、目标电流和位置轨迹状态。
- 用受控电源的电流限制作为独立硬件保护，不依赖软件第一次就正确动作。

现有相关位置：

- 数据接口：SguanFOC/UserData_Function.h 第 78 至 84 行
- PWM 主输出被直接使能：SguanFOC/UserData_Function.h 第 38 至 41 行
- 过流判定：SguanFOC/SguanFOC.c 第 1165 至 1177 行
- 用户状态回调：SguanFOC/UserData_Status.h 第 113 至 150 行

### 3.4 必做：建立位置和速度的唯一单位约定

当前 User_Encoder_ReadRad 返回的是电机轴单圈机械角。GIM6010 的减速比为 8:1，但 SguanFOC 控制核心没有自动把 Target_Pos 转换为输出轴角。

因此当前 Target_Pos 实际更接近“电机轴机械弧度”，而不是输出轴角度。若上位机给定的是输出轴角度，需要明确进行：

~~~text
电机轴目标角 = 输出轴目标角 × 8
电机轴速度 = 输出轴速度 × 8
~~~

建议从现在开始明确命名：

- motor_rad：电机轴机械弧度
- shaft_rad：减速输出轴机械弧度
- elec_rad：电角度
- position_cmd_shaft_rad：上位机位置命令

位置环接收单圈角、相对位置还是多圈绝对位置也必须在接口层定义清楚。上电后没有机械零点开关或掉电保存时，推荐先实现“上电对齐后的相对输出轴位置”；多圈绝对位置另行设计回零或存储策略。

### 3.5 建议：用 PI 速度环完成首版闭环

当前 Open_PI_Control = 0，速度环使用 STA。STA 可用于后续性能优化，但首次建立三环稳定性时，常规 PI 的可解释性和调参路径更清晰。

推荐顺序：

1. 首版电流环使用 PI。
2. 首版速度环使用 PI。
3. 位置环先使用 P 或低增益 PD，位置积分保持为 0。
4. 只有在内环稳定、摩擦/负载特性已知后，再评估 STA、MTPA、弱磁等附加功能。

## 4. 最终推荐的任务划分

### 4.1 目标架构

~~~text
ADC 注入转换完成 / TIM1 同步事件（20 kHz）
  -> 读取本周期电流采样
  -> 电角度预测或读取缓存
  -> Clarke / Park
  -> Id/Iq PI
  -> SVPWM 占空比更新

编码器任务（2 至 5 kHz）
  -> SPI DMA 或受时限的底层轮询
  -> 校验、无磁检测、连续圈数展开
  -> 发布带时间戳的角度、速度、有效性缓存

速度任务（1 kHz）
  -> 读取编码器缓存
  -> 速度 PI
  -> 输出 Iq_ref，并进行限幅

位置任务（250 至 500 Hz）
  -> 位置目标轨迹生成（速度/加速度限制）
  -> 位置 P/PD
  -> 输出 speed_ref，并进行限幅

低优先级任务
  -> VBUS / 温度、状态机、VOFA、RGB、命令解析
~~~

### 4.2 不应放入电流环的内容

下列内容不应继续放进最终的 20 kHz 电流环：

- HAL_SPI_TransmitReceive 阻塞式读取 MT6816；
- HAL_Delay；
- UART 发送或字符串解析；
- RGB DMA 启动；
- 状态机中的复杂处理；
- 浮点格式化、日志输出。

当前 High_Loop 中的同步 MT6816 读取仅适合低频试验。它的 SPI 异常超时为 5 ms，若在高频中断里发生异常，会远超 20 kHz 电流环的 50 us 时间预算。

## 5. 分阶段实施计划

### 阶段 0：可重复构建与测量基线

目标：确保“当前源代码”和“实际烧录固件”是同一版本。

执行项：

1. 解决 Keil 当前设备包/Toolchain 不支持 STM32G431CBTx 的构建问题。
2. 成功全量编译并保存 build log、axf、hex 的时间戳。
3. 固定当前开环最小测试条件：供电电压、电流限制、是否空载、串口波特率。
4. 在 VOFA 记录 Ch0、Ch6、Ch7、Ch11、Ch13、Ch14、Ch17。

验收：

- 构建为 0 error、0 warning。
- 烧录版本可追溯到当前提交/工作区。
- 上电后完成校准，Ch0 进入 IDLE，Ch11 为开环模式。

### 阶段 1：安全链路和硬件接口验收

目标：在不追求性能前先确保失效时电机可控地停止。

执行项：

1. 接入 VBUS、温度、急停、编码器故障的真实输入。
2. 建立统一的 Motor_Disable 输出函数，明确关闭 MOE、清空 PWM、清零目标和 PID 积分。
3. 将 ADC、电流、母线和温度阈值设置为保守值。
4. 用限流电源验证开环对齐阶段不会触发供电保护。

验收：

- 拔掉编码器、模拟低母线、模拟过流时，PWM 在可测的短时间内关断。
- 故障解除后不会自动恢复到带扭矩状态。

### 阶段 2：ADC、电流相序、PWM 和编码器标定

目标：让测量坐标系与功率坐标系一致。

执行项：

1. 记录静止 ADC 原始值、偏置、换算后的两相/三相电流。
2. 用已知电流或外部表计校验电流增益，确认实际是 10 倍还是 20 倍。
3. 低 Uq 开环确认 PWM 相序和转向。
4. 完成编码器方向、机械零位、电角零位校验。
5. 确认 Current_Num 和三个方向符号，写入板级参数表。
6. 示波器确认 ADC 采样窗口避开开关尖峰。

验收：

- 静止时 Id/Iq 无明显漂移。
- 正负小电流的符号正确。
- 同一开环命令在连续上电后转向一致。
- 转子手动旋转一圈时，机械角、电角度、速度方向均符合预期。

### 阶段 3：实时架构重构

目标：将 1 kHz 演示控制改为可支撑伺服的多速率控制。

执行项：

1. 将电流环移到 TIM1/ADC 同步的 10 至 20 kHz 路径。
2. MT6816 改为独立缓存任务；电流环仅读取最新有效角度。
3. 统一每个控制器的离散周期，不再共用不匹配的 TIM_T。
4. 测量每个中断最大执行时间和抖动。
5. 将 UART、DMA、RGB 的中断优先级降至控制中断之下。

验收：

- 电流环执行时间有至少一半以上的周期余量。
- 编码器失败不会阻塞电流环。
- 控制周期与 PID/PLL/LPF 参数一致。

### 阶段 4：受控开环和相序确认

目标：建立可重复的、不会突然大幅加速的开环启动流程。

执行项：

1. 保留对齐阶段，但将对齐电压和时间参数化。
2. 以 V/f 限制配合速度斜坡，从低电角速度平滑升至目标值。
3. 默认命令使用低 Uq、低电角速度，禁止上电直接高 Uq。
4. 记录 Uq、电流、实际机械速度、编码器角。

验收：

- 低电压下可重复正反转。
- 电机不出现明显反冲、卡顿、异常发热。
- 电流不过限，编码器反馈方向正确。

### 阶段 5：电流环闭环

目标：获得稳定、可限流的 Iq 扭矩控制。

执行项：

1. 以实测相电阻 R 和电感 L 重新计算 PI 初值。
2. 从小电流阶跃开始，先调 D 轴，再调 Q 轴。
3. 加入电压饱和、积分抗饱和、Iq 限幅和斜坡。
4. 验证正负 Iq、堵转低电流、负载突变行为。

初值估算可采用：

~~~text
Kp 约等于 L × 电流环角频率
Ki 约等于 R × 电流环角频率
~~~

实际值必须根据采样延迟、PWM、电机参数和波形复核，不能直接套用。

验收：

- 小电流阶跃快速收敛且无持续振铃。
- 指令正负号与扭矩正负号一致。
- 电流限幅和故障关断有效。

### 阶段 6：速度环闭环

目标：在限定 Iq 下稳定控制速度。

执行项：

1. 速度环频率设为约 1 kHz。
2. 位置环先关闭，只调速度 PI。
3. 用低速度、小阶跃、再到额定范围的方式整定。
4. 速度目标使用斜坡，避免直接产生过大 Iq。
5. 验证空载、典型负载、扰动下的稳态误差和超调。

验收：

- 目标阶跃不导致电流持续打满。
- 速度反向时无明显失控或反冲。
- 速度估计不被编码器噪声主导。

### 阶段 7：位置环与轨迹规划

目标：实现输出轴给定角度后的快速、平稳、可重复定位。

执行项：

1. 明确位置命令采用输出轴角度还是电机轴角度。
2. 将位置命令转换为连续位置参考，避免单圈跳变。
3. 在位置环前加入速度、加速度限制；更高要求时加入 S 曲线限加加速度。
4. 先调位置 P，利用已稳定的速度环提供阻尼。
5. 仅在存在稳态偏差时，小幅加入位置积分，并配置积分限幅。
6. 限制 Position.OutMax，不要一开始使用额定最高电机轴速度。
7. 对每次模式切换、重新对齐、急停恢复执行无冲击的参考同步和积分清零。

建议测试序列：

1. 输出轴小角度阶跃，例如 5 度、10 度。
2. 中等角度阶跃，例如 30 度、90 度。
3. 正反向连续阶跃。
4. 相同位置连续 20 次往返。
5. 空载和典型负载下重复上述测试。

验收指标由实际需求定义，至少应包含：

- 最大超调；
- 稳态位置误差；
- 进入误差带的整定时间；
- 最大电流；
- 反向时的回差和抖动；
- 故障与限流时的安全行为。

### 阶段 8：负载验证与长期稳定性

目标：证明系统不是“偶然能跑”，而是在目标工况下可交付。

执行项：

1. 在目标负载、目标供电、不同温度下运行。
2. 测试位置保持、外力扰动、通信中断、编码器短暂错误、母线波动。
3. 保存关键波形和最终参数。
4. 写入参数版本、校准步骤、烧录版本和恢复流程。

验收：

- 同一参数在重复上电后行为一致。
- 长时间运行无异常跳变、热保护误触发或通信影响控制。

## 6. MT6816 代码的优化空间

### 6.1 现状中做得正确的部分

当前 BSP 已按 MT6816 数据手册使用 SPI Mode 3、16 位传输，并解析角度、奇偶校验、无磁告警。引脚映射也与项目文档一致。

当前 SPI 分频为 /32，约 5.3 MHz。MT6816 数据手册给出 SCK 周期最小值 64 ns，因此在时钟源为 170 MHz 的前提下，/16 约 10.6 MHz 仍在时序范围内；/8 约 21.25 MHz 则不应直接使用。

升级至 /16 前必须在实际板上检查波形、校验错误率和线缆/布局裕量。

### 6.2 当前实现的主要问题

1. GetMechRad 每次调用都会同步发起 SPI 读操作。

SguanFOC 的高频路径通过 User_Encoder_ReadRad 调用 GetMechRad；VOFA 打包时又会再次调用 GetMechRad。主循环与中断因此可能竞争同一个 SPI 外设。

2. 同步 SPI 调用带有 5 ms 超时和最多三次重试。

正常读数只需数微秒，但异常路径可能在中断内阻塞远超控制周期。这是把 High_Loop 提高到 10 至 20 kHz 前必须消除的风险。

3. 现有控制核心没有使用 BSP_MT6816_UpdateDt。

该 API 已实现连续圈数、速度和错误计数，但当前 SguanFOC 只取得单圈机械角。连续位置主要依赖库内 PLL 展开，失效诊断信息没有进入控制安全逻辑。

4. 读取失败时只返回上次有效机械角。

短暂失败时保持上次值是合理的，但必须附带数据有效标志和数据龄期。持续失效不能无限伪装成“位置未变化”。

5. BSP_MT6816_Update 的错误路径还需要重新审查速度时间基准。

该函数在本次 SPI 读取前更新时间戳；若本次读取失败、下次恢复成功，则计算速度的 dt 可能没有覆盖真实丢样时长，从而放大速度估计。缓存化改造时应只在成功样本发布后更新时间戳，或使用明确的采样时间戳。

### 6.3 推荐优化顺序

第一步：缓存化。

- 建立 EncoderSample 结构，包含单圈角、连续角、速度、时间戳、有效位、错误码、错误计数。
- 只允许编码器任务访问 SPI。
- 电流环、速度环、位置环、VOFA 只读取最近一份完整缓存。
- 连续角使用 BSP_MT6816_UpdateDt 或等价实现，禁止由多个调用点各自读取 SPI。

第二步：可靠性。

- 设置连续失败阈值和数据过期阈值。
- 无磁、校验错误、SPI 忙/超时分别计数。
- 编码器缓存超过允许龄期时，切到安全状态并关闭 PWM。
- 在启动时明确校验初次读数成功，否则不进入闭环。

第三步：性能。

- 先将 SPI 升至 /16 并用逻辑分析仪验证。
- 将 SPI GPIO 速度与信号完整性一起评估。
- 若 2 至 5 kHz 的编码器更新仍占用过多 CPU，改为 SPI DMA 或 LL 寄存器驱动。
- 电流环只用角度缓存；高速时可根据最近速度进行短时电角度预测。

第四步：位置功能。

- 位置环改用明确的连续电机轴位置或输出轴位置。
- 对上电多圈参考建立回零/保存策略。
- 将编码器错误状态接入 SguanFOC 的状态机，而非只在 VOFA 中观察。

## 7. VOFA 刷新慢的原因与优化计划

### 7.1 物理带宽上限

当前JustFloat包含36个float和4字节帧尾：

~~~text
36 × 4 + 4 = 148 字节/帧
148 × 10 = 1480 串口位/帧（含起始位和停止位）
921600 / 1480 约等于 622.7 帧/秒
~~~

当前921600波特率下，500 Hz、148字节数据帧约占80.3%链路带宽。发送周期固定为2 ms；UART或DMA忙时直接丢弃过期遥测，不阻塞主控制循环。

相关位置：

- 通道数量：SguanFOC/Sguan_printf.h 第 11 至 16 行
- 串口波特率：Core/Src/usart.c 第 43 至 52 行
- DMA 双缓冲发送：SguanFOC/Sguan_printf.c 的 `Printf_Loop`
- 主循环发送时隙：SguanFOC/SguanFOC.c 的 `Printf_Normal_Loop`

### 7.2 当前实现与剩余风险

当前实现已经使用专用 DMA 双缓冲：先把 `Sguan.TXdata` 快照复制到空闲发送缓冲，再启动 DMA，因此主循环更新源数据不会撕裂正在发送的帧。

实现约束如下：

1. 先把快照写入空闲 TX 缓冲。
2. 启动 DMA 后，该缓冲在完成回调前只读。
3. DMA 忙时不等待，不覆盖正在发送的帧；可以丢弃过期遥测，只保留最新快照。
4. Ch6 只按相邻两次 DMA 成功启动计算实际帧率；发送失败不提交统计基准。

### 7.3 分阶段优化方案

第一步：先测量而不提速。

- Ch6 已改为 `20000 / ΔHigh_LoopCount`，直接显示相邻两次 DMA 成功启动之间的实际 VOFA 数据帧发送频率 [Hz]；它用 20 kHz 高频计数作时基，不等于控制环频率本身。
- 新增或规划 TX 成功、丢弃、完成计数，区分“控制慢”和“遥测慢”。
- 在 VOFA 只开必要通道，避免 PC 端过多曲线渲染造成视觉刷新慢。

第二步：固定遥测频率并彻底非阻塞。

- 常规调试当前固定为 500 Hz。
- 发送接口已改为 DMA 忙则直接返回，不进行 while 等待。
- 已使用双缓冲，保证帧一致性。
- UART 和 DMA 中断优先级低于 ADC、PWM/控制中断。

第三步：减少帧尺寸。

- 开环/相序调试只发送 6 至 8 个关键通道。
- 电流环调试发送 Id、Iq、Iq_ref、Uq、角度、状态。
- 位置环调试发送 pos_cmd、pos_ref、pos_fb、speed_ref、speed_fb、Iq_ref、Iq、status。
- 不同调试阶段使用不同的固定通道定义，并同步更新 VOFA 工程。

若后续增加更多通道或提高帧率，缩短帧长度仍是最直接的带宽优化方式。

第四步：复核 921600 链路质量。

当前完整 88 字节帧的理论上限约 1047 Hz。不建议把 21 通道固定在 1 kHz，因为几乎没有剩余带宽；当前 500 Hz 可为命令、主循环抖动和 UART 调度保留余量。

## 8. 控制参数整定原则

### 8.1 必须遵守由内到外的顺序

调参顺序必须是：

~~~text
电流采样正确
  -> 电流环
  -> 速度环
  -> 位置环
  -> 轨迹和前馈
~~~

外环的带宽必须显著低于内环。实用起点是速度环比电流环慢 5 至 10 倍，位置环再比速度环慢 3 至 5 倍；具体比例依据机械惯量、齿隙、编码器噪声和目标响应调整。

### 8.2 现有默认参数不能直接作为最终参数

UserData_Motor.h 中的 R、L、磁链来自资料和估算，尤其电感量必须用实物确认。任何电感单位、相电感/线电感定义的误解都会让电流 PI 初值相差数量级。

建议保留“资料初值”和“台架实测值”两组记录，不要在没有原始测量记录的情况下直接覆盖。

### 8.3 位置环的推荐首版形态

首版不要追求位置积分和高微分增益。建议：

1. 使用位置 P 产生 speed_ref。
2. 使用稳定的速度 PI 产生 Iq_ref。
3. 使用稳定的电流 PI 产生 Ud/Uq。
4. 用速度、加速度限制约束位置阶跃。
5. 只有确认摩擦导致静差后，再少量增加位置积分。

减速器的回差、摩擦和弹性会限制最终可达到的快速定位性能。若出现高频抖动，优先检查速度估计、位置滤波、机械回差和电流环，而不是先增大 Position.Kp。

## 9. 当前源码中的重点关注文件

- SguanFOC/UserData_Motor.h：电机、相序、电流采样、方向和保护阈值。

- Core/Src/tim.c：TIM1 PWM、ADC 触发、TIM2 周期。
- Core/Src/usart.c：串口波特率和 DMA 配置。

## 10. 推荐的下一步

在不改动大架构前，最值得先做的是“阶段 0 + 阶段 1 + 阶段 2 的准备工作”：

1. 先恢复可重复构建、烧录和日志记录。
2. 明确 Current_Num 与三相映射。
3. 补上 VBUS、温度、编码器失效和硬关 PWM 的安全闭环。
4. 统一当前 1 kHz 试验阶段的 TIM_T。
5. 用低压限流完成开环、ADC、编码器方向的台架验收。

这些完成后，再决定是先实施“非阻塞 VOFA + MT6816 缓存化”，还是直接实施“20 kHz 电流环架构”。对最终稳定位置环而言，建议先完成编码器缓存化和安全链路，再改电流环调度。
