# GIM6010 控制器开发 — 工作区导航

> 本目录 = **源工程**（CubeMX 生成的固件工程，Keil MDK 打开 `MDK-ARM\GIM6010_V0.0.uvprojx`）。
> 开发流程：**先冻结需求（01）→ 再出设计文档（02）→ 你说"开始生成代码"后我写代码 → 代码落回本目录源工程，副本与日志放 03**。

## 目录结构

```
3、SguanFOC库文件\                  ← 源工程（代码最终改这里）
├─ 01_需求确认\                    ← 【你现在要填的地方】
│   ├─ GIM6010控制器_需求清单.md      ← 主清单（逐项回答/勾选，最重要）
│   ├─ CubeMX配置变更清单.md          ← 需要你在 CubeMX 里改的配置 + 我持续提醒
│   └─ 附图_原理图与硬件资料\          ← 放原理图/手册/照片，AI 识别后回填
├─ 02_设计文档\                     ← 需求冻结后：AI 产出的协议/状态机/上位机步骤设计
├─ 03_工程归档\                     ← 需求快照、代码变更包、编译日志
├─ AI辅助设计\                      ← 已有：移植实施计划与决策记录.md（背景参考）
├─ APP\                            ← 应用层（当前为空，后续代码落点）
├─ BSP\                            ← 板级驱动（ADC/MT6816/WS2812B，部分为空壳待补）
├─ Core\                           ← CubeMX 生成（只动 USER CODE 段）
├─ Drivers\                        ← HAL/CMSIS（不动）
├─ SguanFOC V3.0.1\                ← 电机库（核心不动，只配 UserData_*）
├─ MDK-ARM\                        ← Keil 工程（uvprojx）
└─ 资料\                           ← 你原来的资料
```

## 你现在需要做的（一次性）
1. 打开并填写 `01_需求确认\GIM6010控制器_需求清单.md`（可直接在里面改，也可口头回复"全部按默认"+只改个别项）
2. 原理图/手册/截图放入 `01_需求确认\附图_原理图与硬件资料\`，在清单附录 A 登记文件名
3. 把 `01_需求确认\CubeMX配置变更清单.md` 里你能先确认的项标注（不必现在去改 CubeMX，等清单 C-1~C-7 汇总后一次性执行）

## 协作规则（写给我，供你监督）
- 你说 **"开始生成代码"** 之前，我不写任何固件代码，只做文档与提问。
- HAL 生成代码 / SguanFOC 库核心：不修改；需改配置走"变更清单"由你执行。
- 每轮交付都会检查 CubeMX 变更清单，未完成项会反复提醒你。
